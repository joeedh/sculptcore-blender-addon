I would hold cache acceptance. The packet implements configuration separation and first-contact caching, but exposes two correctness holes and leaves the principal execution oracles unproved. This review uses only the supplied source.

**Correctness blockers**

1. **Mesh execution accepts calls outside the transaction that owns the cache.** `beginStep()` resets the cache, but `endStep()` neither retires it nor closes an execution admission flag. Both mesh resolved entry points check mesh ownership and the dab frame, without checking an open step. Consequently, `beginStep → A → endStep → external coordinate edit → applyResolved(A)` can reuse A’s old factors: geometry identity and topology stamp remain unchanged. This is an accepted public call sequence in the supplied implementation, even if normal callers avoid it. Grid execution already rejects the equivalent sequence through `stepOpen_` and log-serial checks.

   **Minimal correction:** require an open mesh transaction before resolved execution, with transaction ownership validation where applicable. Clearing at `endStep()` alone prevents this particular reuse but still permits execution without a transaction.

   Citations: [mesh admission](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/brush_executor.cc:153), lines 153–159 and 247–251; [mesh lifecycle](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/brush_executor.h:2339), lines 2339–2383; [cache identity](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/prepared_cavity.h:43), lines 43–50; [grid admission](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/grid_executor.cc:38), lines 38–42.

2. **The reusable BFS visitation token wraps without clearing its stamps.** Every cache miss increments a `uint32_t` token. At wrap to zero, untouched vertices also have stamp zero and are incorrectly treated as visited. Later tokens can collide with older stamps too. The resulting wrong factor is then frozen in the cache. Reusing one scratch across configurations makes the counter span all configuration/vertex evaluations. This is a long-lifetime correctness defect, not evidence of a likely ordinary-stroke failure.

   **Minimal correction:** on token wrap, clear visitation stamps and restart with a nonzero token. Test by placing the token near its maximum; billions of evaluations are unnecessary.

   Citations: [scratch initialization and token increment](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/automask.h:83), lines 83–100 and 113–117; neighbor rejection at lines 148–154; [persistent cache fill](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/prepared_cavity.h:70), lines 70–84 and 120.

**Acceptance refinements — separate from demonstrated defects**

- **Prove independent command effects through actual deformation.** Both tested commands have zero strength. The assertions inspect the cache’s active column, so they can pass even if a kernel fails to consume cavity factors. Add nonzero mask/draw/smooth execution with independently expected outputs, two enabled configurations in one program, and a cavity-off control. The standalone case proves only that evaluations occurred. [Tests](/C:/dev/blender/sculptcore-blender-addon/engine/tests/prepared_cavity_cases.h:85), lines 85–123 and 184–187.

- **Capture and check each configuration’s first-contact oracle.** The initial A comparison is useful, but B is checked only by configuration count. Returning to A permits any evaluation increase through `afterA >= afterB`; newly contacted vertices receive no expected-value comparison. Capture co/no immediately before each fill, verify B numerically, and assert the exact new-contact evaluation delta for A. Add non-accumulating contact, strict-radius boundary, and larger-secondary-radius cases. Compare immediate/deferred policies against their own snapshots. [Tests](/C:/dev/blender/sculptcore-blender-addon/engine/tests/prepared_cavity_cases.h:124), lines 124–157; [contact implementation](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/brush_executor.h:1035), lines 1035–1047.

- **Exercise topology and identity invalidation, rather than merely observing validity.** The supplied lifecycle tests cover begin-step reset and same-domain attach. They do not change topology within a transaction, test stale ring1 on a frozen mesh, replace domain identity, or verify subsequent raw/prepared execution and undo/cancel. The malformed-command test snapshots evaluation count only; it does not establish its comment’s claim of no topology work. [Tests](/C:/dev/blender/sculptcore-blender-addon/engine/tests/prepared_cavity_cases.h:158), lines 158–211.

- **Measure warm-path cost beyond BFS counts.** Configuration lookup linearly scans retained entries and can compare all 256 samples per candidate. Creating C configurations differing near the LUT’s end therefore permits quadratic cumulative lookup work. Every stage also visits the selected leaf union and writes identity outside support. Unchanged evaluation counts prove neither cheap lookup nor absence of capacity-sized work inside `AttrData::resize`, whose implementation is absent. Add configuration-comparison, allocation and visited-vertex measurements; use hash-assisted lookup with full equality if needed. [Cache lookup](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/prepared_cavity.h:43), lines 43–67; [stage traversal](/C:/dev/blender/sculptcore-blender-addon/engine/source/brush/brush_executor.h:1035), lines 1035–1047.

The full configuration key, lazy in-support entry creation, reusable active column, and later-command ring1 requirement are implemented. Their presence should receive credit; the missing execution and lifetime evidence should remain explicit acceptance conditions.
