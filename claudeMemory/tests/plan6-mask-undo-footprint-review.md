The footprint strategy is sound for an existing mask channel, but I would block acceptance on two gaps. This is a source-only review; the packet contains no test results establishing that the gates pass.

1. **Capture must cover creation of the mask channel itself.** The fold looks up `"mask"` before flushing; `captureGrids` silently returns for a missing channel. The flush then creates the channel and can seed entire finer levels. Thus the supplied path permits an edit that creates finer allocations after capture has found no channel. The plan specifies snapshots for absent *levels*, but does not specify capture when the *channel* is absent. There is no supplied precondition excluding this case.  
   **Minimal correction:** explicitly capture logical absence for every finer level when `"mask"` is missing, with resolution after creation; alternatively, establish and enforce channel existence before capture without allocating finer levels. Add a first-mask-stroke test proving undo restores finer allocation absence and redo restores the complete seeded data.  
   **Citations:** `engine/source/brush/grid_executor.h:139–143`; `engine/source/subdiv/grid_stroke_log.cc:137–146`; `engine/source/subdiv/grid_domain.cc:274–284,310–340`; `engine/source/subdiv/grids.cc:411–419`; plan lines 24–39.

2. **The repeated-capture complexity gate still has a quadratic coarse path.** Keeping finer dedup separate does not repair the coarse capture executed alongside it. For channel indices ≥32, recapturing an already stamped grid scans `s.blocks`. Recapturing T previously captured grids of that channel requires Θ(T²) block comparisons. Mask is not guaranteed an index below 32. This is a concrete conflict with a whole-path “no quadratic duplicate scans” acceptance claim, although ordinary first capture avoids that branch.  
   **Minimal correction:** replace the coarse high-index fallback with indexed membership, or explicitly narrow the complexity claim to the new finer helper and acknowledge the existing limitation. Test repeated capture with mask above index 31; repeated complete folds cannot exercise one open step because each fold closes it.  
   **Citations:** `engine/source/subdiv/grid_stroke_log.cc:60–80`; `engine/source/brush/grid_executor.h:139–143,168–170`; plan lines 35–39,54–58.

The following are **acceptance refinements, not additional architectural blockers**:

- **Separate allocated-level locality from whole-level seeding.** Occurrence-grid capture covers allocated finer levels: propagation only writes grids in its touched list, even as the interpolation footprint expands within each grid. An absent level is the explicit exception: it is seeded whole, so the owning snapshot must retain the whole resulting allocation for redo. The plan already accommodates this. Test an allocated → absent → allocated finer chain, with nonuniform values on unrelated grids, to verify both cases and continued delta propagation past the seeded level.  
  **Citations:** `engine/source/brush/grid_executor.h:122–132`; `engine/source/subdiv/grids.cc:354–381,411–457`; plan lines 22–39.

- **Make byte accounting assertions directional.** Measure `bytes()` after capture, undo, redo, redo-branch truncation and history eviction. After undo, an originally absent level’s complete allocation can move into history; count actual held chunks or compressed buffers, without also charging `rawFloats` as an additional allocation. “Touched-grid scaling” applies to allocated-level snapshot payload, not that whole-level redo allocation.  
  **Citations:** `engine/source/subdiv/grids.h:457–469`; `engine/source/subdiv/grid_stroke_log.cc:44–50,304–328`; plan lines 47–58.

- **Define the scaling metric and strengthen the oracle.** Existing fold and propagation code initialize arrays over all vertices/grids, so total execution is already not strictly proportional to touched grids. Gate incremental snapshot storage and dedup work separately. Require bitwise store-value restoration, unchanged unrelated grids, earliest-value retention across overlapping captures, and a zero-delta case that creates no finer allocation. The propagation function returns before seeding when no deltas exist.  
  **Citations:** `engine/source/brush/grid_executor.h:111–121`; `engine/source/subdiv/grid_domain.cc:323–329`; `engine/source/subdiv/grids.cc:348–381`; plan lines 52–60.
