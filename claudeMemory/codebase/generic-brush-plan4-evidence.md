### Delivered model and native contracts

- `brush_properties/registry.py`, `storage.py` and `resolver.py` provide strict
  typed definitions, persistent values/policies, unique ordered device stacks,
  custom curves and plural positions. Reads do not copy inherited data. Effective
  value and stack setters resolve independently and preserve dormant local data.
  Unknown payloads remain intact; unsupported future schemas reject mutation.
- `authoring.py`, `legacy.py` and the frozen catalogues register independently of
  the DLL. The production catalogue has 23 definitions and 62 shared curve
  declarations. Missing kernels do not erase values; five historical uniform
  names map to seven frozen IDs. Registration and manifest reconciliation remain
  separate. The saved readiness switch defaults off.
- `adapters.py` reads/writes authoritative native RNA; `bindings.py` retains
  resource, enum, color and specialized curve widgets. Per-operation native
  bounds, numeric type, units and tooltips remain available, including changing
  pixel/world size domains. The path-keyed
  [coverage inventory](../design/generic-brush-native-coverage-v1.json) accounts
  for all 882 frozen rows: 407 supported paths and 475 preserved exclusions.
  No new scalar mirror replaces a native setting.
- Strength/size pressure uses the current native capability or shadow flag even
  after richer stack metadata exists. Disabled/generated selections preserve
  native mappings. Scene pressure and non-pressure inputs use owner-aware owned
  mappings. Explicit empty stacks disable native pressure; later native flag
  changes normalize to one pressure entry. Size aliases share one semantic stack.
- Coupled size edits preserve the current native setter asymmetry and validate
  the complete resulting pair. Cancel restores the exact original pair. Cavity
  fields share the compound Brush/Scene policy and pin their effective block
  before toggles. Geometry conversions remain separate from authoring; legacy
  PINCH's extra local-strength source is explicit and diagnosed.
- The fork's explicit `ID.authoring_edit_begin/commit/cancel` API captures bounded
  generic trees and optional scoped native settings, with UID-based references,
  complete memory accounting, rollback and one visible undo step. It preserves
  unknown system/custom properties, retires stale wrappers, and restores without
  Python callbacks. See the installed fork
  [API documentation](../../../main/doc/python_api/rst/info_property_authoring.rst).
  Addon `edits.py` groups effective-owner gestures; consuming operators omit
  automatic UNDO flags. The actual Brush curve template uses this boundary.

## Persistent atomic scalar records — 2026-09-17

Completed the [reviewed atomic scalar plan](../plans/generic-brush-atomic-scalars.md).
`brush_properties/storage.py` now implements persistent FLOAT32/INT32/BOOL values,
value inheritance, independent stack-inheritance flags and generic Scene unified
flags. Effective-owner writes preserve dormant values. Native strength delegates
to authoritative native settings and stores only its non-native policies.

Metadata uses versioned custom IDProperty groups keyed by a stable identifier
hash, with full identifier/type validation. This supersedes the earlier metadata
CollectionProperty proposal. The future declared CurveMapping bank remains in a
separate namespace on the same owner; metadata writes preserve existing declared
curve runtime identities. Absent reads/default policies do not create records.
Unknown siblings survive exact native copying, including typed arrays, empty
collections, flags, UI metadata and ID references. Future schema and malformed
known metadata reject; explicit scalar writes can repair a malformed scalar.

The fork adds the engine-agnostic `ID.id_properties_update_atomic(root, operations)`
API. It stages bounded scalar SET/DELETE batches and UI metadata on a native clone,
publishes once, and notifies the actual owner only on semantic change. Validation
failure leaves presence, values, metadata, references and asset dirty state intact.
It accepts exact builtin inputs, holds the GIL, preserves the caller's GC state,
and rejects invalid owners/write contexts before no-op handling. It does not
create undo steps or mutate ID-reference topology. Published metadata replaces its
raw root; consumers must reacquire nested wrappers. Owned curves remain separate.

Two fresh adversarial reviewers covered native transaction safety and addon
semantics before implementation, then audited the implementation. Corrections
include editable linked assets, complete normalized UI comparisons, opaque-tree
bounds, callback-free parsing, schema checks before native writes, integer bounds,
and genuine typed/quantized reads. Implementation reproductions caught lost int
enum choices and float-backed UI step overflow; both now have regression cases.
Final focused audits reported no remaining findings.

defects; their requested cases were added for static stored data, reverse

## Saved plural positions — 2026-09-17

Completed the [reviewed placement slice](../plans/generic-brush-persistent-positions.md).
`PersistentOwnerStore` now reads, writes and resets local placement lists on Brush
and Scene, including native-backed definitions whose value/stack capability is
unavailable. Placement never follows effective value or stack ownership.

An absent override returns definition defaults without allocating. An explicit
empty list hides all locations. An explicit list equal to today's defaults remains
authored if a later registry changes defaults; reset returns to the new defaults.
Lists retain authored order; product UI sorting/rendering remains Plan 7.

Each location has a stable 54-byte base32 key and validated full identity. The
atomic scalar API publishes the complete version/order/active fields in one
commit. Reset deletes only override headers and retains dormant payloads. Unknown
fields remain losslessly preserved. Future/mistyped placement versions reject
placement edits while other scalar/stack/policy edits preserve them opaquely.
Bounds are 128 distinct locations, 1024 UTF-8 bytes per location, and signed-int32
sort indices; unknown Unicode location identifiers remain accepted. Defaults and
saved writes share this validation, including forged descriptor rejection.

Two fresh adversarial plan reviews clarified reset/no-allocation, partial headers,
native-capability independence, location collisions, bounded JSON and definition
evolution. Implementation audits found no defects and requested additional active
reader corruption and non-scalar DELETE rollback cases; those now pass. Existing
atomic and stack tests cover native static-type mismatch rejection, which this
slice's shared transaction retains.
